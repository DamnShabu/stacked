# Known issues

These are the open bugs reported against [Cordial](https://github.com/luohoa97/cordial/issues),
the project Stacked is forked from, and where each one stands in Stacked. The
engine layer is the same code, so anything reported there applies here unless
this page says otherwise.

"Changed, unverified" means the code now handles the reported cause, but
nobody has confirmed it on the hardware or compositor where the bug happens.
If you have that setup, a report either way helps. "Changed, partly verified"
means it was measured working on a reproduction here, but not on the
reporters' setups.

| Issue | Symptom | In Stacked |
|---|---|---|
| [#31](https://github.com/luohoa97/cordial/issues/31) | Keyboard dies after another app takes focus (Hyprland) | **Fixed in the code the fork started from.** Hyprland names the canvas surface on refocus, and that surface is now accepted. |
| [#52](https://github.com/luohoa97/cordial/issues/52) | Client sometimes hangs on exit and ignores SIGTERM | **Changed, unverified.** If the engine's shutdown callbacks haven't returned after 10 seconds, the client says so and exits. Cookies are saved before those callbacks start. `CORDIAL_TEARDOWN_TIMEOUT_S` changes the limit. |
| [#39](https://github.com/luohoa97/cordial/issues/39) | Fullscreen freezes, and leaving it crashes | **Changed, unverified.** While the title bar animated in and out, the engine got a new size, and rebuilt its swapchain, on every frame; it now gets one at most every 100 ms, and the final size once it holds. The crash on leaving was traced upstream ([PR #72](https://github.com/luohoa97/cordial/pull/72), on RADV) to a `VK_SUBOPTIMAL_KHR` image acquire, which is now reported to the engine as success; that fix is upstream's measurement and has not been reproduced here. |
| [#41](https://github.com/luohoa97/cordial/issues/41) | X11: camera spins 180°, and movement continues for a few seconds | **Half changed, unverified.** When the window loses focus, keys still held are now released, as the Wayland backend already did. The 180° spin is not understood yet. |
| [#56](https://github.com/luohoa97/cordial/issues/56) | Hyprland never confirms the pointer lock, and the cursor drifts | **Partly addressed, unverified.** Fullscreen *confinement* is now placed on the surface Hyprland gives pointer focus to, and pointer input on that surface reaches the game in fullscreen. The camera *lock* is unchanged. |
| — | Pointer lock never engages on KDE Plasma (Wayland); the cursor leaves the window during a camera drag or in first person | **Changed, unverified.** KWin only locks the pointer inside the window's input region, which had the game area cut out of it, and only applies a lock or its release when the window next commits. Both are now handled. Not yet run on Plasma; `CORDIAL_TRACE_MOUSE=1` shows whether the compositor sends `locked`. |
| [#36](https://github.com/luohoa97/cordial/issues/36) | First touch on a touchscreen crashes | **Fixed, unverified on hardware.** GDK's touch handler took the engine's `wl_surface` user data as a `GdkSurface` without checking, and the canvas had none; it now carries an unmapped one. Reproduced and fixed upstream on GTK 4.22.4. Checked with a touch injected into a nested compositor (`tools/touch-compositor/`), not on a real touchscreen. If it still crashes, run with `CORDIAL_TRACE_TOUCH=1` and report the last line printed. |
| [#44](https://github.com/luohoa97/cordial/issues/44) | Crash on second launch ("TaskScheduler before flags") | **Mitigated in the code the fork started from.** The client waits for the settings to be delivered before starting the engine's task scheduler. It is still open upstream. |
| [#35](https://github.com/luohoa97/cordial/issues/35) | SIGSEGV at launch on the Steam Deck | **Open.** The DeviceUtils error in the report also appears in logs of runs that didn't crash. Vulkan results reach the engine unmodified, except a `VK_SUBOPTIMAL_KHR` image acquire, now reported as success (see #39); whether that touches this crash is unknown. |
| [#38](https://github.com/luohoa97/cordial/issues/38) | No window on COSMIC, KWin and wlroots compositors | **Open.** It doesn't reproduce on a headless sway 1.9 with GTK 4.14, and the report's log isn't reachable from here. |
| [#53](https://github.com/luohoa97/cordial/issues/53), [#54](https://github.com/luohoa97/cordial/issues/54) | Typing a camera sensitivity greys the screen | **Changed, partly verified.** The grey screen was reproduced on a nested KWin with no working Vulkan: GTK's GL renderer stops drawing beside the engine's GLES. Stacked now picks GTK's cairo renderer there, and on compositors without dmabuf, and lowers the game only under a frame GTK has drawn ([ADR-047](adr/ADR-047-the-canvas-is-lowered-only-under-a-presented-frame.md)). Not confirmed on the reporters' machines; if it still greys, include the `[gtk] renderer:` line from the output. |
| [#92](https://github.com/luohoa97/cordial/issues/92) | Signed-in client sometimes stuck at startup: one frame, then nothing | **Changed, unverified.** The settings call that the race depends on now waits for the engine's first render step ([ADR-065](adr/ADR-065-the-late-post-waits-for-the-first-render-step.md); `CORDIAL_POST_GATE=0` turns it off). If a start still freezes, `stacked play` stops it and starts it again, up to twice (`CORDIAL_NO_FREEZE_RESTART=1` turns that off). A freeze that remains with `post gate: ... posting` in the output is not this race. |
| [#64](https://github.com/luohoa97/cordial/issues/64), [#29](https://github.com/luohoa97/cordial/issues/29) | Keyboard sometimes dead after joining an experience | **Changed, partly verified.** While a game starts, Stacked now hovers the pointer where it last was, four times a second; in one place, on one client under a nested sway, 0 of 18 joins walked without it and 4 of 4 with it ([movement-keys.md](analysis/movement-keys.md)). <!-- ORCHESTRATOR: adjust once the stale-focused-text-box fix for teleports lands. --> **Not yet covered: a keyboard that dies after a teleport, which has a separate cause still being fixed.** If the keyboard is dead, run with `CORDIAL_TRACE_KEYS=1`, press W and paste only the W `[cordial] key` lines (every key is printed, passwords included): `result=gated` means Stacked dropped it, `result=ok` on `path=native` means it reached the engine. |
