# Stacked 0.21.6

On a monitor faster than 60 Hz, the frame rate now stays at the display's
refresh rate for the whole session. Before, it ran at, say, 165 for about two
minutes after the window opened and then dropped to 60 and stayed there. The
same applied to a frame rate set with `stacked config set fps_cap`.

## What was wrong

Roblox re-downloads its settings every two minutes and replaces the ones
Stacked gave it at launch, including the frame-rate target. Stacked now
notices when that happens and gives its settings back a few seconds later.

So for about five seconds after each refresh, every two minutes, the frame
rate may drop to 60 before it comes back. This was measured with a frame-rate
cap of 5 on the sign-in screen, where the cap now holds through every refresh
and without the change is lost at the first one. A rate above 60 in a game has
not been measured directly, but it is the same setting.

## Which file to download

The same as [0.21.3](v0.21.3.md): the `.AppImage` for any distribution, or the
`.deb`, `.rpm`, Arch package or `.flatpak` for yours. If you use the Roblox
manager, press Update Stacked.

## What is still broken

- The frame rate may dip to 60 for a few seconds every two minutes, as above.
- From [0.21.5](v0.21.5.md): the text box editor on niri may send clicks to the
  game. Not yet tested.
- From [0.21.4](v0.21.4.md): web pages may not load over HTTPS from the
  AppImage on non-Debian systems, and two people running the same version on
  one computer cannot both open web windows.

Everything in the "What is still broken" section of the
[0.21.0 notes](v0.21.0.md) still applies. In short:

- updating Roblox at launch has not yet been seen working end to end;
- no window on COSMIC, KWin or some wlroots compositors;
- a crash at launch on some machines, including the Steam Deck;
- the keyboard is sometimes dead after joining an experience;
- a startup freeze on signed-in profiles, which comes in bursts.

[`docs/known-issues.md`](../known-issues.md) says where each one stands.
