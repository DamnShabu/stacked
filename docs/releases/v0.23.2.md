# Stacked 0.23.2

Two window fixes, mainly for KDE Plasma and Hyprland.

## What changed

- **Clicking just outside a floating game window reaches the window behind
  it.** The transparent shadow around the game window used to take every
  click, so a window showing through that band could not be brought forward.
  Only the narrow resize border next to the window's edge is Stacked's now.
  Maximised, tiled and fullscreen windows have no shadow and are unchanged.
- **On KDE Plasma and Hyprland, the cursor should land where the game left it
  when a right-click camera drag ends**, rather than back where the drag
  started.
- Building from source now needs Rust 1.92. That was already true in practice;
  `Cargo.toml` now says so instead of claiming 1.75.

## Which file to download

The same as [0.21.3](v0.21.3.md): the `.AppImage` for any distribution, or the
`.deb`, `.rpm`, Arch package or `.flatpak` for yours. If you use the Roblox
manager, press Update Stacked, then launch your accounts again.

## What is still broken

- **Neither fix has been seen working on KDE Plasma or Hyprland.** Both were
  worked out from the Wayland protocol and the code and tested in isolation,
  not in a running game on those desktops.
- If the game window still seems to stay on top of other windows when you
  click well away from it, or in fullscreen, this release does not fix that.
  Please open [an issue](https://github.com/DamnShabu/stacked/issues) with
  `stacked logs --zip` attached.
- If the cursor still jumps back to an earlier click after a right-click
  drag, the same applies. Say which desktop you use, and whether it is X11 or
  Wayland.
- Everything listed under [0.23.0](v0.23.0.md#what-is-still-broken) still
  applies.
