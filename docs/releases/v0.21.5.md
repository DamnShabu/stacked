# Stacked 0.21.5

On niri, a web window such as a game's Servers list can now be used. Before,
it opened, but the cursor disappeared over it and clicks and scrolling still
went to the game underneath, so it could not be clicked, scrolled or closed.

## What was wrong

The game is drawn on its own surface inside Stacked's window. While a web
window is open, Stacked moves that surface behind the rest of the window so
the web window can take the pointer. niri does not take that ordering into
account when it decides which surface the pointer is over, so the game's
surface went on receiving it.

0.21.5 also stops the game's surface accepting the pointer at all while a
web window is open, and gives it back when the last one closes. This was
measured on niri. Other compositors already handled the first step and are
expected to behave the same as before, but have not been re-tested.

## Which file to download

The same as [0.21.3](v0.21.3.md): the `.AppImage` for any distribution, or the
`.deb`, `.rpm`, Arch package or `.flatpak` for yours. If you use the Roblox
manager, press Update Stacked.

## What is still broken

- **The text box editor on niri may have the same problem**: clicks over a
  focused text box could go to the game. Not yet tested.
- From [0.21.4](v0.21.4.md): web pages may not load over HTTPS from the
  AppImage on non-Debian systems, and two people running the same version on
  one computer cannot both open web windows.

Everything in the "What is still broken" section of the
[0.21.0 notes](v0.21.0.md) still applies. In short:

- updating Roblox at launch has not yet been seen working end to end;
- no window on COSMIC, KWin or some wlroots compositors;
- a crash at launch on some machines, including the Steam Deck;
- the keyboard is sometimes dead after joining an experience;
- a startup freeze on signed-in profiles, which comes in bursts.

[`docs/known-issues.md`](../known-issues.md) says where each one stands.
